Reviewing and Building a Package

The Review Delivery Package window scans the working material, inspects the candidate files, and shows what the package will contain. It is not modal: you can keep working in Open Salamander while you review.

Lists

RulesEach rule of the specification with its role, required flag, selected and expected counts, and status (OK, Errors, Warnings, Missing). Select All rules or one rule to filter the other lists.
ItemsCandidate files with their target path in the package, size, details (pages, page size, pixel size, resolution), approval, licence, and status. Clear the check box to exclude a file; excluding all files of a required rule is reported as an omission. Missing expected items are listed as Missing.
FindingsErrors, warnings, and notes with their code. Double-click a finding (or press Enter) to focus the file in the working panel.

The filter offers All items, Problems only, Omissions, Not included (files no rule selected, and forbidden content that is never packaged), and Superseded (older revisions).

Actions

ApproveApproves the selected items of rules that require reviewer approval.
Approve all in ruleApproves all included items of the selected rule.
Show in panelFocuses the selected file in the working panel.
OverrideShown only when the specification allows it: accepts an error with a recorded reason of at least 10 characters. Some errors can never be overridden.
Re-scanScans and inspects again. Decisions are kept for files that did not change.
Save reportSaves a plain-text report of rules, items, and findings.
BuildEnabled when no errors remain and, if warnings exist, I have reviewed all warnings is checked. Any change clears the check box.

What a build does

  1. Creates a hidden unfinished package folder in the staging location.
  2. Copies every included file (never moves it), keeping the last-write time, and verifies each copy by SHA-256. Only the main data of a file is copied.
  3. Writes CONTENTS.txt, manifest.csv, and manifest.json (names can be changed by the specification).
  4. Checks that the folder contains exactly the planned files, then publishes it under the final name.
  5. Writes a build record <package>.handoff-build.json beside the package. It contains internal paths, the user and computer name, reviewer decisions, and the full specification, so keep it out of the delivery if that information must stay internal.

Cancelling, an error, or a changed source file stops the build: the files copied so far are removed and nothing appears under the final package name. The Result dialog shows Verified — ready for review, Verified with warnings, or Not built with the reason.
