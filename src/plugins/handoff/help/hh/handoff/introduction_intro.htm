Open Salamander: Plugins: Delivery Handoff: Introduction

Introducing Delivery Handoff

Delivery Handoff builds and verifies professional delivery packages. One panel shows your working material; the other panel shows the staging location where the delivery package is created. A reusable delivery specification (a *.handoff.json file) describes what a package must contain: required documents, naming conventions, file formats, PDF page sizes, image dimensions, allowed content, approval and licence evidence, and supporting assets.

The plugin assembles the candidate files, flags omissions and problems, lets you review and approve them, copies the files into a new package folder, and writes a manifest (manifest.json, manifest.csv) and a contents list (CONTENTS.txt). Every copied file is verified by SHA-256 before the package is published under its final name. Working files are never moved or modified.

Quick start: "Prepare the client delivery"

  1. Show the project folder in the left panel and the folder for deliveries (for example D:\Deliveries) in the right panel. Keep the left panel active.
  2. If the project has no specification yet, choose Plugins / Delivery Handoff / New Specification from Template and pick Client delivery (example). It is saved in the project's .handoff folder.
  3. Choose Plugins / Delivery Handoff / Build Delivery Package. The specification from the .handoff folder is preselected. Enter the variables (for example the client code, project code, and revision) and choose Scan.
  4. In the Review Delivery Package window, resolve the reported errors, approve documents that need reviewer approval, and choose Build.
  5. The result reads Verified — ready for review and the new package folder is focused in the staging panel.

Commands

Build Delivery PackageOpens a build session for the active panel (working material) and the inactive panel (staging location). See Building a Delivery Package.
Verify Delivery PackageVerifies the focused package folder, the current folder, or a folder you choose. See Verifying a Delivery Package.
Validate SpecificationChecks a specification file and lists problems with line and column. See Validating a Specification.
New Specification from TemplateCreates a starter specification. See Creating a Specification.

No hot keys are assigned by default; you can assign them in Plugins Manager.

Troubleshooting

Build is disabledErrors remain, or warnings have not been acknowledged. Use the Problems only filter.
Package folder already existsPackages are never overwritten. Increase the revision variable or remove the old package.
Source changed since reviewA working file was edited after the scan. Choose Re-scan.
Publication blockedAnother program (indexer, antivirus, Explorer preview) used a file in the unfinished package. Try again; the unfinished folder is kept and offered for removal next time.
Page inspection unavailableWindows could not open the PDF for page inspection (damaged file, unusual encryption, or Windows PDF component unavailable).
Hidden .…handoff-….partial folderA build was interrupted. The next build in that staging location offers to remove it.
